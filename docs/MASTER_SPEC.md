# Project WIND — 자체 엔진 기반 2D 싱글 플레이 액션 RPG 통합 개발 명세서

- 문서 버전: 2.1
- 상태: 개발 기준 초안
- 대상 플랫폼: Windows PC 우선
- 언어: C++20
- 빌드: CMake
- 렌더링·입력·오디오 기반: SDL3
- 저장: 로컬 저장 파일(JSON)
- 기본 원칙: 자체 게임 엔진 + 싱글 플레이 + 눈에 보이는 완성도 우선 + 단계별 검증

> 이 문서는 고전적인 2D 픽셀 아트 RPG에서 영감을 얻은 **혼자 하는(싱글 플레이) 액션 RPG**를 독자적으로 개발하기 위한 통합 명세서다. 특정 게임의 소스 코드, 맵, 스프라이트, 음악, 대사, 상표 또는 기타 보호 대상 콘텐츠를 무단 복제하지 않는다. 모든 게임 콘텐츠와 브랜드는 독자적으로 제작한다.

> **버전 2.0 변경 요약** (자세한 이유는 `docs/DECISIONS/0007-single-player-visual-focus.md`)
> - MMORPG → 싱글 플레이 액션 RPG. 서버, 네트워크(ENet), 계정, 데이터베이스(PostgreSQL), 채팅·친구·파티를 범위에서 뺀다.
> - 한 칸씩 이동 → 픽셀 단위 자유 8방향 이동.
> - 고전 자동 공방 → 실시간 액션 전투(직접 휘두르고 피하기).
> - 화면 연출(조명, 파티클, 날씨, 낮과 밤, 타격감, 화면 전환, UI 애니메이션)을 핵심 기능으로 격상한다.
> - 단계 0·1은 완료된 상태로 두고, 단계 2부터 새 계획을 따른다.
> - 2.1: 개발 단계를 0~20의 21개 작은 단계로 다시 나눴다(19장).

# 1. 프로젝트 목표와 범위

## 1.1 목표

독자적인 2D 픽셀 아트 액션 RPG를 상용 게임 엔진 없이 개발한다. 플레이어는 혼자 필드를 탐험하고, 몬스터와 실시간으로 싸우고, 아이템을 얻고, 성장하고, 이야기를 따라간다. **"보기만 해도 기분 좋은 화면"**을 게임 규칙만큼 중요한 목표로 둔다.

## 1.2 핵심 경험

- 따뜻하고 생동감 있는 픽셀 아트 월드: 흔들리는 풀, 흐르는 물, 반짝이는 빛
- 부드러운 자유 이동과 읽기 쉬운 캐릭터 실루엣
- 손맛 있는 실시간 전투: 히트스톱, 넉백, 번쩍임, 피해 숫자, 화면 흔들림
- 조명과 시간대: 낮과 밤, 횃불, 동굴의 어둠
- 날씨와 분위기: 비, 눈, 안개, 떠다니는 꽃잎과 반딧불
- 성장과 수집: 룬을 모아 원하는 능력치를 올리는 소울라이크식 레벨업, 무기 3종, 별빛 마술, 드롭, 장비
- 여러 지역을 잇는 탐험과 부드러운 화면 전환
- 언제든 저장하고 이어서 하기

## 1.3 범위 단계

### 플레이 가능 버전(수직 슬라이스)
- 지역 2~3개(초원, 숲, 동굴)와 화면 전환
- 자유 이동, 실시간 공격, 회피
- 몬스터 2~3종과 AI
- HP·사망·부활
- 룬·레벨업(능력치 분배), 쓰러지면 룬 절반 손실
- 드롭·인벤토리·간단한 장비
- 조명, 파티클, 낮과 밤, 날씨 1종 이상
- 저장·불러오기
- 타이틀 화면, 일시정지 메뉴, 설정
- 효과음과 배경 음악

### 확장 버전
- NPC 대화, 퀘스트, 상점
- 직업 또는 무기별 기술
- 보스 전투와 컷신 수준의 연출
- 더 많은 지역과 던전
- 맵 편집 보조 도구

### 출시 버전
- 초보자 안내
- 접근성 옵션(화면 흔들림·번쩍임 줄이기, 키 재설정)
- 성능 측정과 하드웨어 제한 사항 문서
- 설치 없이 실행 가능한 릴리스 패키지

## 1.4 제외 범위

다음은 만들지 않는다: 온라인 서버, 멀티플레이, 계정·로그인, 원격 데이터베이스, 채팅, 친구, 파티, 거래, 결제, 안티치트. 모바일과 3D도 제외한다. 필요해지면 새 결정 기록을 남기고 다시 검토한다.

## 1.5 제품 원칙

1. 플레이 가능한 작은 버전을 먼저 완성한다.
2. **화면에 보이는 결과로 진척을 판단한다.** 각 단계는 직접 보고 확인할 수 있는 장면으로 끝난다.
3. 게임 규칙(시뮬레이션)과 화면 연출(프레젠테이션)을 분리한다. 연출이 규칙을 바꾸지 않는다.
4. 콘텐츠는 코드와 분리한다.
5. 모든 중요한 변경은 테스트와 문서에 반영한다.
6. 과도한 추상화보다 이해하기 쉬운 모듈을 우선한다.
7. 목표 수치는 측정 전까지 보장으로 표현하지 않는다.

## 2.2 의존성 정책

- 외부 라이브러리의 버전과 라이선스를 `DEPENDENCIES.md`에 기록한다.
- 재현 가능한 빌드를 위해 버전을 고정한다.
- 라이선스가 불명확한 라이브러리·폰트·음원을 사용하지 않는다.
- 새 라이브러리는 도입 이유, 대안, 라이선스, 유지보수 상태를 기록한다.
- 외부 라이브러리로 게임 엔진 전체를 대체하지 않는다.

## 2.3 코드 품질 규칙

- C++20 표준을 사용한다.
- 소유권은 RAII와 명확한 수명 규칙으로 관리한다.
- `new/delete` 직접 사용을 최소화한다.
- 오류를 무시하지 말고 로그와 적절한 오류 반환으로 처리한다.
- 전역 가변 상태를 최소화한다.
- 게임 규칙 코드는 SDL과 렌더링에 의존하지 않는다.
- 연출 수치(흔들림 세기, 파티클 수, 색)는 코드에 흩어 놓지 않고 데이터나 이름 있는 상수로 둔다.
- 무관한 파일을 대량으로 재작성하지 않는다.

## 2.4 클래스별 파일 분리(모듈화) 규칙

코드는 클래스 단위로 나눈다. 파일 하나를 열면 그 파일이 무엇을 하는지 한눈에 알 수 있어야 한다.

1. **클래스 하나 = 파일 한 쌍.** `class`(또는 함수가 있는 `struct`) 하나마다 `이름.hpp` + `이름.cpp`를 만든다. 파일 이름은 클래스 이름을 snake_case로 쓴다. 예: `GridMover` → `grid_mover.hpp`/`grid_mover.cpp`.
2. **같이 둬도 되는 것.** 그 클래스만 쓰는 작은 `enum`이나 함수 없는 값 묶음 `struct`(예: `GridMover::MoveResult`)는 같은 파일에 둔다. 다른 클래스도 쓰기 시작하면 자기 파일로 옮긴다.
3. **값 타입 모음은 예외.** 함수가 거의 없는 작은 값 타입 여러 개(예: `Vec2`, `RectF`)는 주제별 헤더 하나(`math.hpp`)에 모아도 된다.
4. **자유 함수 묶음.** 클래스가 없는 도우미 함수는 주제별 파일 한 쌍에 모은다(예: `coordinates.hpp`). 한 파일에 서로 다른 주제를 섞지 않는다.
5. **한 클래스 = 한 가지 일.** 클래스 설명을 "그리고" 없이 한 문장으로 쓸 수 없으면 나눈다. `.cpp`가 약 300줄을 넘으면 나눌 수 있는지 검토한다.
6. **폴더 = 모듈.** 관련 클래스는 같은 폴더(`engine/fx/`, `game/combat/` 등)에 두고, 폴더는 3.3의 의존 방향을 따른다. 아래 층(engine)이 위 층(game)을 `#include`하지 않는다.
7. **헤더는 가볍게.** 헤더에는 필요한 것만 `#include`하고, 포인터·참조로만 쓰는 타입은 전방 선언한다. SDL 헤더는 SDL 계층(3.3)의 `.cpp`에서만 포함한다.
8. **테스트도 클래스별.** 클래스 `Foo`의 테스트는 `foo_tests.cpp`에 둔다.

기존 코드 중 이 규칙과 다른 곳(예: 한 헤더에 클래스가 둘 이상)은 그 코드를 다음에 고치는 작업에서 함께 나누거나, 별도의 정리 작업으로 나눈다. 정리 작업은 동작을 바꾸지 않고, 빌드·테스트로 확인한다.

# 3. 시스템 아키텍처

## 3.1 논리 구성

```text
[Windows 실행 파일 wind_client]
  ├─ Platform (SDL3: 창, 이벤트, 오디오 장치)
  ├─ Engine (게임과 무관한 재사용 부품)
  │   ├─ Game Loop / Frame Clock
  │   ├─ Renderer / Render Queue / Render Targets
  │   ├─ Tilemap / Camera
  │   ├─ Animation / Tween
  │   ├─ Particles / Lighting / Post Effects
  │   ├─ Input
  │   ├─ Audio
  │   ├─ UI (위젯, 텍스트)
  │   └─ Resource Manager
  ├─ Game Presentation (규칙 결과를 화면·소리로 보여 줌)
  │   ├─ 엔티티 그리기, 타격감, 피해 숫자
  │   ├─ 날씨, 시간대, 지역 분위기
  │   └─ HUD, 메뉴, 대화창
  └─ Game Simulation (SDL 없는 게임 규칙)
      ├─ World / Maps / Collision
      ├─ Movement / Combat / AI
      ├─ Stats / Inventory / Quests
      └─ Save Data
                │
                ▼
     [로컬 저장 파일 (%APPDATA%\ProjectWIND\saves)]
```

## 3.2 시뮬레이션과 프레젠테이션의 분리

- **시뮬레이션**은 고정 박자(기본 60 Hz)로 돌아가며 위치, 충돌, HP·MP·스태미나, 피해, 룬, 아이템을 결정한다. 같은 입력과 같은 난수 시드면 같은 결과가 나와야 한다(결정론). SDL 없이 단위 테스트할 수 있다.
- **프레젠테이션**은 시뮬레이션이 남긴 상태와 **이벤트**(예: `Hit`, `Died`, `LevelUp`, `ItemPicked`)를 읽어 화면과 소리로 보여 준다. 렌더 프레임마다 돌아가며 두 시뮬레이션 박자 사이를 보간한다.
- 연출이 시뮬레이션 결과를 바꾸지 않는다. 예외는 **히트스톱**처럼 의도적으로 시뮬레이션 시간을 잠깐 멈추는 연출이며, 이 경우 시뮬레이션의 공식 입력(`time_scale`)으로 전달한다.

싱글 플레이이므로 치트 방지를 위한 권한 검증은 필요 없다. 그러나 **저장 파일과 콘텐츠 파일은 손상될 수 있는 외부 입력**으로 보고 검증한다(15장).

## 3.3 모듈 의존성

| 모듈 | 위치 | 역할 | 의존 가능 |
|---|---|---|---|
| `wind_shared` | `shared/` | SDL 없는 기반: 로그, 수학 타입, 방향, 맵 모델, 콘텐츠 로더, 저장 형식 | 표준 라이브러리, spdlog, nlohmann/json |
| `wind_engine_core` | `client/src/engine/` 중 SDL 없는 부분 | 박자 시계, 카메라, 입력 상태, 렌더 큐, 애니메이션, 트윈, 파티클 시뮬레이션 | `wind_shared` |
| `wind_game_core` | `client/src/game/` 중 SDL 없는 부분 | 게임 규칙 시뮬레이션 | `wind_shared`, `wind_engine_core` |
| 엔진 SDL 계층 | `engine/platform`, `engine/render/renderer.*`, `engine/resources`, `engine/audio` | SDL 호출이 있는 유일한 곳 | SDL3 |
| `wind_client` | 실행 파일 | 화면 상태(타이틀, 필드, 메뉴), 연결 | 전부 |

- 엔진 모듈은 게임 도메인(몬스터, 아이템)을 모른다.
- 게임 규칙 모듈은 SDL을 모른다.
- `shared`는 `client`에 의존하지 않는다.
- 단계 2에서 `server/` 디렉터리와 ENet을 제거한다.

# 5. 자체 게임 엔진 상세 설계

## 5.1 게임 루프

한 프레임의 순서:
1. OS 이벤트 수집
2. 입력 상태 갱신
3. 고정 박자 시뮬레이션 갱신(누적 시간만큼, 상한 있음)
4. 시뮬레이션 이벤트를 프레젠테이션으로 전달
5. 연출 갱신(애니메이션, 트윈, 파티클, 카메라 흔들림, 날씨, 시간대)
6. 렌더링(월드 → 조명 → 후처리 → UI)
7. 오디오 처리
8. 디버그 계측

- 시뮬레이션 박자: 60 Hz. 한 프레임 최대 0.25초, 최대 5박자까지만 따라잡는다(ADR 0006).
- 렌더링은 두 시뮬레이션 상태 사이를 `alpha`로 보간해 부드럽게 그린다.
- 60 FPS를 목표로 하되 하드웨어에 따라 보장한다고 표현하지 않는다.

## 5.2 렌더링

기본 렌더러는 SDL3 렌더러를 쓴다. 게임 코드는 SDL 함수를 직접 부르지 않고 엔진의 `Renderer`와 `RenderQueue`만 쓴다.

필수 기능:
- 텍스처·아틀라스 로딩
- 스프라이트 소스 사각형, 위치, 크기, 회전, 반전
- 색 곱하기(tint)와 알파
- **블렌드 모드**: 일반, 더하기(빛·불꽃), 곱하기(그림자·어둠)
- **렌더 타깃**: 월드를 논리 해상도 텍스처에 그린 뒤 조명·후처리를 얹고 화면에 확대
- 카메라 변환과 레이어 정렬
- 화면 밖 컬링
- 타일맵 배치 렌더링
- 디버그 오버레이
- 렌더링 통계(그리기 호출 수, 컬링 수, 파티클 수)

## 5.3 좌표계

- 시뮬레이션 위치는 **월드 픽셀 좌표(실수)**를 쓴다. 타일 좌표는 충돌·맵 조회용으로 변환해 쓴다.
- 변환 함수(타일 ↔ 월드 ↔ 화면)는 한 곳(`engine/map/coordinates`)에서 관리한다.
- 타일 크기 32×32 논리 픽셀(설정값). 스프라이트 크기와 타일 크기를 같다고 가정하지 않는다.

## 5.4 픽셀 렌더링

- 논리 해상도 640×360, 정수 배율 확대, 최근접 이웃 필터(ADR 0006).
- 카메라 위치는 그릴 때 정수 픽셀로 맞춘다. 캐릭터도 그릴 때 정수 픽셀로 맞춰 떨림을 막는다.
- 확대 후에 얹는 효과(예: 화면 전체 색보정)는 논리 해상도 기준으로 계산해 픽셀이 뭉개지지 않게 한다.
- UI는 같은 논리 해상도에 그리되 월드 카메라의 영향을 받지 않는다.

## 5.5 타일맵 및 렌더 레이어

그리기 순서:
1. 바닥(Ground)
2. 바닥 장식(GroundDecor) — 애니메이션 타일 포함(물, 꽃)
3. 그림자(Shadows) — 캐릭터·오브젝트 발밑 그림자
4. Y 정렬(YSorted) — 낮은 오브젝트, 캐릭터, 몬스터, 발 위치 y로 정렬
5. 높은 오브젝트(HighObjects) — 나뭇잎, 지붕
6. 월드 효과(WorldFx) — 파티클, 피해 숫자
7. 조명(Lighting) — 어둠 덮개와 빛
8. 날씨·전경(Weather/Foreground)
9. 후처리(PostFx) — 화면 번쩍임, 비네트, 페이드
10. UI
11. 디버그(DebugOverlay)

정렬 기준은 (레이어, 발 위치 y, 넣은 순서)로 명시한다. 컨테이너 순서에 의존하지 않는다.

타일 속성: 타일 ID, 이름, 통행 가능 여부, 그리기 레이어, **애니메이션 프레임**(선택), **흔들림(바람) 여부**(선택), **빛 방출**(선택).

## 5.6 애니메이션과 트윈

- 스프라이트 애니메이션은 데이터로 정의한다: `idle`, `walk`, `attack`, `hit`, `dodge`, `death` (+ 필요 시 `cast`).
- 방향: 그림은 4방향부터 시작하고 8방향 이동은 가장 가까운 4방향 그림을 쓴다. 그림이 준비되면 8방향 그림으로 늘린다.
- 프레임별 **이벤트 표시**(예: 공격 3번째 프레임에서 `hit_active`, 걷기 2·4번째 프레임에서 `footstep`)를 지원한다.
- **트윈**: 값 하나를 시간에 따라 부드럽게 바꾸는 도구. 이징 함수(linear, ease-in/out quad·cubic, back, elastic)를 제공한다. UI 등장, 카메라 이동, 아이템 튀어 오르기 등에 쓴다.
- 애니메이션 상태는 시뮬레이션 상태를 따라간다. 공격 판정 시점은 시뮬레이션의 공격 데이터(9.2)가 정하고, 그림은 그 시점에 맞춰 만든다.

## 5.7 리소스 수명

리소스 관리자는 다음을 제공한다: 경로 정규화, 콘텐츠 루트 밖 경로 거부, 로딩 실패 진단(한 번만 로그), 중복 로딩 방지 캐시, 자리 표시 그림, 명시적 해제, 통계. 폰트와 소리도 같은 규칙을 따른다.

## 5.8 입력

- 키보드 상태(held/pressed/released), 키 반복 무시, 창 포커스를 잃으면 모든 키 해제.
- 게임 동작(Action) 단위 키 바인딩, 키 설정 저장.
- **입력 버퍼**: 공격·회피 입력을 짧게(기본 0.15초) 기억했다가 가능해지는 순간 실행한다. 손맛의 핵심이다.
- UI가 입력을 가져갔는지(UI capture) 명확히 관리한다.
- 게임패드는 확장 버전에서 지원한다(SDL3 게임패드 API).

## 5.9 오디오

- 효과음과 배경 음악 분리, 마스터·음악·효과음 볼륨.
- 같은 효과음의 동시 재생 수 제한과 약간의 음높이 무작위 변화(반복감 줄이기).
- 지역 전환 시 음악 교차 페이드.
- 오디오가 실패해도 게임은 계속된다.
- 첫 형식은 WAV. 압축 형식이 필요하면 디코더 도입을 결정 기록으로 남긴다.

## 5.10 디버그 기능

개발 빌드에서 표시할 수 있게 한다:
- FPS, 프레임 시간, 놓친 박자 수
- 플레이어 위치(월드·타일), 방향, 상태
- 충돌 영역과 공격 판정 영역(히트박스·허트박스)
- 엔티티 수, 파티클 수, 빛 개수, 그리기 호출 수
- 리소스 통계
- 시간대 강제 변경, 날씨 강제 변경, 연출 끄기 토글
- **스크린샷 키**(F12): 논리 해상도 원본을 PNG로 저장 — 화면 품질 검토용

# 6. 비주얼 디렉션과 연출 시스템

이 장은 "눈에 보이는 것"의 기준이다. 세부 수치와 팔레트는 `docs/VISUALS.md`에 두고, 이 장의 기준과 충돌하지 않게 관리한다.

## 6.1 아트 방향

- 스타일: 따뜻한 판타지 픽셀 아트. 동양 판타지 분위기를 참고하되 특정 게임을 따라 그리지 않는다.
- 타일 32×32, 캐릭터 프레임 약 32×48. 화면 640×360에서 가로 20칸, 세로 약 11칸이 보인다.
- **팔레트**: 프로젝트 공용 팔레트(32~64색)를 정해 모든 그림이 따른다. 지역별로 색감(초원 = 따뜻한 녹색, 동굴 = 차가운 청색)을 다르게 하되 같은 팔레트 안에서 고른다.
- 캐릭터는 배경보다 대비가 높아야 한다. 어두운 외곽선 또는 밝은 테두리 중 하나로 통일한다.
- 모든 엔티티는 발밑 그림자를 가진다.
- 시험용 그림은 생성 스크립트로 만들되, 실제 아트로 교체할 수 있도록 파일 형식과 크기 규칙을 지킨다.

## 6.2 살아 있는 월드

- 애니메이션 타일: 물 반짝임, 꽃 흔들림(타일 데이터로 프레임 지정).
- 바람 흔들림: 풀·나뭇잎 스프라이트를 시간에 따라 몇 픽셀 흔든다.
- 주변 파티클: 꽃잎, 반딧불, 먼지, 낙엽 — 지역 데이터로 지정.
- 캐릭터 주변 반응: 걸을 때 먼지, 풀숲을 지날 때 풀잎, 물가에서 물결.

## 6.3 조명

- **어둠 덮개 + 빛 방식**: 화면 크기의 조명 텍스처를 주변광 색(예: 밤 = 짙은 남색)으로 채우고, 빛(부드러운 원형 그라데이션 그림)을 더하기 블렌딩으로 그린 뒤, 월드 위에 곱하기 블렌딩으로 덮는다.
- 빛 데이터: 위치, 반지름, 색, 세기, 깜빡임(횃불), 맥박(마법).
- 빛을 내는 것: 횃불, 창문, 마법, 반딧불, 특정 타일, 일부 공격 효과.
- 실내·동굴 맵은 주변광이 어둡다. 맵 데이터로 주변광을 지정한다.
- 화면 밖 빛은 그리지 않는다. 빛 개수 상한을 두고 디버그에 표시한다.

## 6.4 낮과 밤

- 게임 시간: 기본 실제 1분 = 게임 1시간(설정값).
- 시간대별 주변광 색과 세기를 색 곡선 데이터로 정의하고 사이를 보간한다(새벽 분홍, 낮 흰색, 노을 주황, 밤 남색).
- 밤에는 일부 빛이 자동으로 켜진다(창문, 가로등).
- 실내·동굴 맵은 시간대 영향을 받지 않도록 맵에서 끌 수 있다.

## 6.5 날씨

- 비: 빗줄기 파티클, 바닥 튀김, 약간 어두운 주변광, 빗소리.
- 눈: 천천히 흔들리며 내리는 파티클.
- 안개: 천천히 흐르는 반투명 층.
- 지역별 날씨 확률과 지속 시간은 데이터로 정한다. 날씨 전환은 몇 초에 걸쳐 서서히 한다.

## 6.6 파티클 시스템

- 파티클 효과는 데이터(`content/fx/*.json`)로 정의한다: 방출 수·속도, 수명, 시작·끝 크기, 색 그라데이션, 중력, 공기 저항, 블렌드 모드, 그림.
- 파티클 시뮬레이션은 SDL 없는 엔진 코어에 두고 단위 테스트한다.
- 미리 정한 최대 개수(기본 4,000)를 넘지 않는다. 넘으면 새 파티클을 버리고 통계에 센다.
- 파티클은 화면 연출이다. 게임 규칙에 영향을 주지 않는다.

## 6.7 타격감(Game Feel)

공격이 맞았을 때 다음을 조합한다. 각 수치는 무기·공격 데이터로 조절한다.

| 연출 | 기본값(조정 가능) | 설명 |
|---|---|---|
| 히트스톱 | 0.05~0.1초 | 맞는 순간 공격자와 대상의 시간을 잠깐 멈춘다 |
| 흰색 번쩍임 | 0.08초 | 맞은 대상을 하얗게 칠한다 |
| 넉백 | 거리·감속 | 시뮬레이션이 실제로 밀어낸다 |
| 화면 흔들림 | 세기·시간, 감쇠 | 트라우마 값 방식(세기² 비례) |
| 피해 숫자 | 튀어 오르며 사라짐 | 치명타는 크게, 색 다르게 |
| 타격 파티클 | 불꽃·조각 | 무기 종류별 |
| 효과음 | 무기·대상별 | 음높이 무작위 변화 |

- 접근성: 설정에서 화면 흔들림과 번쩍임을 끄거나 줄일 수 있다.
- 플레이어가 맞을 때는 화면 가장자리 붉은 비네트와 짧은 무적 깜빡임을 쓴다.

## 6.8 화면 전환과 카메라 연출

- 화면 전환: 페이드, 원형 아이리스, 픽셀 디졸브 중 선택. 지역 이동, 사망, 불러오기에 쓴다.
- 카메라: 부드러운 추적(지수 감쇠), 이동 방향으로 약간 앞을 보기(look-ahead), 맵 경계 고정, 흔들림, 보스·이벤트 때 줌(정수 배율 유지 범위 안에서) 또는 지점 이동.

## 6.9 UI 비주얼

- 9-슬라이스 창 테두리, 아이콘, 픽셀 폰트(한글 지원).
- 창 열고 닫을 때 트윈 애니메이션(0.15~0.25초).
- HP·MP 바는 줄어든 양을 잠깐 다른 색으로 남겼다가 따라 줄인다(지연 바).
- 레벨업, 아이템 획득, 지역 이름 등장 같은 알림 배너.
- 모든 UI 문자열은 데이터로 두고 글자 잘림을 검사한다.

# 7. 월드·맵·이동 명세

## 7.1 맵 데이터

맵은 ID, 표시 이름, 타일 크기, 너비, 높이, 타일셋, 타일 레이어, 스폰 위치, 출구, **분위기 설정**(주변광, 시간대 영향 여부, 날씨 표, 주변 파티클, 배경 음악), **엔티티 배치**(몬스터 스폰, NPC, 빛, 상자, 세이브 포인트)를 가진다.

현재 형식(단계 1에서 구현, `docs/ENGINE.md`)을 기반으로 확장한다. 새 필드는 `schema_version`을 올리거나 선택 필드로 추가하고, 변경을 문서에 기록한다.

```json
{
  "schema_version": 2,
  "map_id": "starter_meadow",
  "display_name": "초원의 입구",
  "tile_size": 32,
  "width": 40,
  "height": 30,
  "tileset": "tilesets/meadow.json",
  "layers": [{"name": "ground", "render_layer": "ground", "tiles": []}],
  "spawn_points": [{"id": "default", "x": 6, "y": 12}],
  "exits": [{"area": {"x": 39, "y": 10, "w": 1, "h": 3}, "to_map": "maps/forest.json", "to_spawn": "west"}],
  "ambience": {"ambient_light": "daycycle", "weather_table": "weather/meadow.json", "ambient_fx": ["fx/petals.json"], "music": "audio/music/meadow.wav"},
  "entities": [{"type": "monster_spawner", "monster": "monsters/slime.json", "x": 20, "y": 15, "count": 3},
               {"type": "save_point", "id": "meadow_cushion", "x": 8, "y": 10}]
}
```

이 예시는 방향을 보여 주는 개념 스키마다. 정확한 필드는 구현 단계에서 `docs/ENGINE.md`에 확정한다.

## 7.2 이동 규칙

- 픽셀 단위 자유 이동, 8방향 입력(대각선은 길이를 정규화해 더 빠르지 않게).
- 속도·가속·감속을 데이터로 둔다(미끄러지지 않으면서도 딱딱하지 않게).
- 충돌체는 **발 부분의 작은 사각형(AABB)**이다. 그림 크기와 분리한다.
- 타일 충돌: x축과 y축을 따로 이동·검사해 벽을 따라 미끄러지게 한다.
- 모서리 보정: 모서리에 살짝 걸리면 몇 픽셀 옆으로 밀어 지나가게 한다.
- 회피(구르기): 짧은 거리를 빠르게 이동하고 짧은 무적 시간을 가진다. 재사용 대기시간이 있다. 스태미나를 쓴다.
- 달리기: 이동 중 Shift를 누르고 있으면 걷기보다 빠르게 달린다. 스태미나를 쓴다.
- 맵 경계 밖으로 나갈 수 없다.

### 7.2.1 스태미나

스태미나는 달리기, 회피, 무기 공격에 쓰는 기력이다. 게임 규칙이므로 고정 박자 시뮬레이션에서 계산하고 SDL 없이 테스트한다. 수치는 데이터(이동 조정값)로 두며, 기본값은 다음과 같다.

| 항목 | 기본값 | 설명 |
|---|---|---|
| 최대 스태미나 | 100 (지구력 10) | 지구력 곡선(8.2)으로 정해진다. 단계 8~12에서는 100 고정 |
| 달리기 속도 | 걷기 최고 속도 × 1.5 (165 px/s) | |
| 달리기 소모 | 초당 25 | 실제로 움직이는 동안만 소모. 제자리에서 Shift만 누르면 소모 없음 |
| 회피 소모 | 1회 25 | 스태미나가 25 미만이면 회피가 나가지 않는다(입력 버퍼는 유지) |
| 공격 소모 | 무기마다 (8.4) | 스태미나가 0보다 많으면 모자라도 공격은 나가고 0이 된다(소울라이크식). 0이면 나가지 않는다. 마술은 스태미나 대신 MP를 쓴다 |
| 회복 대기 | 0.6초 | 마지막으로 쓴 뒤 이 시간이 지나야 회복 시작 |
| 회복 속도 | 초당 30 | |
| 지침 | 0이 되면 지침 상태 | 25까지 회복하기 전에는 달리기·회피·공격 불가. 0 근처에서 달리기가 켜졌다 꺼졌다 덜덜거리지 않게 한다 |

- 스태미나는 0~최대 범위를 벗어나지 않는다(경계값 테스트).
- 지침 상태일 때는 숨찬 연출(땀방울 파티클 등)과 바 깜빡임으로 알린다. 연출은 결과를 바꾸지 않는다.

## 7.3 엔티티 충돌

- 플레이어와 몬스터는 서로 겹치지 않도록 부드럽게 밀어낸다(밀어내기 힘 제한).
- 공격 판정(히트박스)과 이동 충돌체는 따로 관리한다.
- 많은 엔티티 검사를 위해 균일 격자 공간 분할을 쓴다(엔티티 수가 늘면 측정 후 적용).

## 7.4 지역 전환

1. 플레이어 충돌체가 출구 영역에 들어간다.
2. 입력을 잠그고 전환 연출(페이드 등)을 시작한다.
3. 화면이 가려지면 새 맵을 불러오고 검증한다.
4. 목적지 스폰 위치에 플레이어를 놓고 카메라를 즉시 맞춘다.
5. 음악·분위기를 교차 전환하고 화면을 다시 연다.
6. 지역 이름 배너를 띄운다.

새 맵 불러오기에 실패하면 이전 맵에 머물고 오류를 로그와 화면 알림으로 보여 준다.

# 8. 캐릭터·성장 명세

## 8.1 주인공

싱글 플레이이므로 주인공 한 명으로 시작한다. 이름은 새 게임 시작 때 입력한다(길이 1~12자, 표시 가능한 문자만).

시작 상태: 다섯 능력치 모두 10(레벨 1), 롱소드, 마술 "별빛 조각" 하나, 룬 0개.

성장 방식은 **소울라이크식**이다. 경험치 대신 **룬**을 모으고, 세이브 포인트에서 룬을 내고 레벨을 올리며, 올릴 때마다 원하는 능력치 하나를 1 올린다. 쓰러지면 가진 룬의 절반을 잃는다. 결정 기록: `docs/DECISIONS/0009-soulslike-progression.md`.

다른 게임을 참고하되 그 게임의 고유 이름·설정·수식을 그대로 가져오지 않는다. 능력치·무기·마술 이름과 수치는 이 문서에서 새로 정한다.

## 8.2 능력치

원본 능력치는 다섯 개다. 저장 파일에는 이 다섯 개와 룬만 저장하고, 나머지는 모두 계산으로 구한다.

| 능력치 | id | 올리면 |
|---|---|---|
| 생명력 | `vigor` | 최대 HP |
| 정신력 | `mind` | 최대 MP |
| 지구력 | `endurance` | 최대 스태미나 |
| 힘 | `strength` | 물리 공격력(무기 힘 보정), 들 수 있는 무게 |
| 지능 | `intelligence` | 마법 공격력, 쓸 수 있는 마술(요구 지능), 마술 칸 수 |

- 각 능력치는 1~60. 레벨 = 다섯 능력치의 합 − 49 (시작 1, 최대 251). 레벨은 저장하지 않고 계산한다.
- 현재값: hp_current, mp_current, stamina_current. HP·MP는 저장하고, 스태미나는 저장하지 않는다(불러오면 가득 참).
- MP는 마술에 쓴다. 초당 2씩 천천히 회복한다(캣닢 쿠션에서 쉬면 가득 참).
- 파생값(최대 HP·MP·스태미나, 들 수 있는 무게, 힘 보너스, 지능 보너스, 마술 칸 수)은 **능력치 곡선 데이터**(`content/progression/stat_curves.json`)에서 구한다. 곡선은 (능력치, 값) 점 목록이고 점 사이는 직선으로 잇는다. 높은 구간은 기울기를 줄여서 한 능력치만 올리면 효율이 떨어지게 한다(소프트 캡).

기본 곡선 (구현 전 시작값, 조정 가능):

| 파생값 | 능력치 10 | 20 | 30 | 40 | 60 |
|---|---|---|---|---|---|
| 최대 HP (생명력) | 100 | 190 | 280 | 360 | 450 |
| 최대 MP (정신력) | 50 | 100 | 150 | 180 | 210 |
| 최대 스태미나 (지구력) | 100 | 130 | 160 | 180 | 200 |
| 들 수 있는 무게 (힘) | 8 | 14 | 19 | 24 | 30 |
| 힘 보너스 (힘) | 0.0 | 0.5 | 0.8 | 1.0 | 1.2 |
| 지능 보너스 (지능) | 0.0 | 0.5 | 0.8 | 1.0 | 1.2 |
| 마술 칸 (지능) | 2 | 3 | 3 | 4 | 4 |

- 물리 공격력 = 무기 기본 공격력 × (1 + 무기 힘 보정 × 힘 보너스)
- 마법 공격력 = 기본 마력 12 × (1 + 지능 보너스). 마술 위력(8.6)을 곱해서 쓴다. 지팡이(촉매)는 확장 버전에서 마력 값을 바꾸는 장비로 추가한다.
- 파생 능력치는 원본 능력치 + 장비 + 효과에서 **한 곳의 계산 함수**로 구한다. 곡선 데이터는 불러올 때 검증한다(능력치 1~60 범위, 점은 오름차순, 값은 음수 아님).

## 8.3 룬과 레벨업

- **룬**은 몬스터를 쓰러뜨리거나 상자·퀘스트 보상으로 얻는다. 레벨업 비용이자 상점 화폐(11.3)다. 소지 상한 999,999,999(정수 범위 검사).
- **레벨업**은 세이브 포인트(8.7)의 레벨업 화면에서만 한다.
  - 능력치마다 [−] [+]로 올릴 양을 고르고, 바뀔 값(예: 최대 HP 100 → 118, 들 수 있는 무게 8 → 9)을 미리 보여 준다.
  - 확정하면 필요한 룬을 한 번에 내고 능력치를 올린다. 룬이 모자라면 아무것도 바뀌지 않는다(전부 성공 또는 전부 실패, 테스트).
  - 한 번에 여러 레벨을 올릴 수 있다.
- **비용**: 레벨 L에서 L+1로 가는 데 드는 룬 = `floor(a + b·(L−1) + c·(L−1)²)`. 계수는 데이터(`content/progression/levels.json`)이며 기본값 a = 100, b = 40, c = 6 (레벨 1→2: 100, 10→11: 946, 30→31: 6,306). 비용 함수는 순수 함수로 만들고 경계값을 테스트한다.
- 레벨업 연출 이벤트: 빛기둥 파티클, 효과음, 배너("레벨 5"), 바가 늘어나는 트윈.
- **쓰러지면** 가진 룬의 절반을 잃는다: 잃는 양 = `floor(소지 룬 / 2)`. 레벨과 능력치는 잃지 않는다. 잃은 룬은 되찾을 수 없다(초기 규칙, 23.2).

## 8.4 무기

무기는 데이터 파일(`content/weapons/*.json`)이다. 공격 동작은 9.2 공격 데이터를 순서대로 이어 붙인 콤보로 정한다. 공격마다 스태미나를 쓴다(7.2.1).

| 무기 | 무게 | 기본 공격력 | 힘 보정 | 휘두르기 (준비/판정/후딜, 초) | 1타 스태미나 | 콤보 | 특징 |
|---|---|---|---|---|---|---|---|
| 단검 | 2 | 8 | 0.4 | 빠름 0.04 / 0.06 / 0.10 | 8 | 4타 | 짧은 사거리, 치명타 확률 +10%, 휘두르는 중 이동 덜 멈춤 |
| 롱소드 | 6 | 14 | 0.8 | 보통 0.08 / 0.10 / 0.18 | 14 | 3타 | 기준 무기, 시작 무기 |
| 대검 | 14 | 26 | 1.2 | 느림 0.22 / 0.14 / 0.36 | 26 | 2타 | 넓게 휘두름, 넉백·히트스톱·화면 흔들림 큼 |

- 무기 데이터: `id`, `name`, `weight`, `base_power`, `strength_scaling`, `stamina_per_attack`, `attacks`(콤보 순서의 공격 데이터 경로), 선택 `crit_bonus`.
- **무게**: 무기 무게가 들 수 있는 무게(8.2, 힘)보다 무거우면 장착은 되지만 **무거움** 상태가 된다. 무거움: 공격 구간 시간 ×1.3, 공격 스태미나 ×1.5. 장비 화면에 "무게 14 / 8"처럼 빨갛게 표시한다. 시작 힘 10(무게 8)으로는 대검이 무겁고, 힘 20(무게 14)부터 제대로 쓴다.
- 확장 버전: 창, 활, 지팡이(마력 촉매), 무기 강화.

## 8.5 캐릭터 상태 머신

상태: `idle`, `moving`, `running`, `attacking`, `casting`(마술 시전·광선 유지), `dodging`, `hit`(경직), `exhausted`(지침 표시용 하위 상태, 이동은 됨), `resting`(세이브 포인트 메뉴), `dead`, `transitioning`(지역 이동), `in_dialogue`.

허용 전이를 표로 명시하고 테스트한다. 예: `dead`에서는 공격·이동 불가, `attacking` 중 회피는 공격 데이터의 "취소 가능 구간"에서만, `casting` 중 회피는 시전 시작 전 또는 광선 유지 중에만(광선은 끊김), `resting` 중에는 게임 입력 차단.

## 8.6 마술 (별빛 마술)

마술은 데이터 파일(`content/spells/*.json`)이다. 요구 지능보다 지능이 낮으면 마술 칸에 넣을 수 없다. 마술 칸 수는 지능 곡선(8.2)으로 정해지고(2~4칸), 마술 칸은 세이브 포인트에서 바꾼다. 필드에서는 Q로 칸 안의 마술을 차례로 고르고 L/C로 쓴다.

처음 마술 다섯 개 (자주 쓰이는 소울라이크 마술 유형을 참고해 새로 만든 이름과 수치):

| 마술 | id | 요구 지능 | MP | 시전 | 위력 | 동작 |
|---|---|---|---|---|---|---|
| 별빛 조각 | `star_shard` | 10 | 6 | 0.25초 | 1.0 | 작고 빠른 빛 탄 하나. 시작 마술, 기본기 |
| 큰 별빛 조각 | `great_star_shard` | 16 | 14 | 0.6초 | 2.2 | 느리고 큰 빛 탄, 넉백 큼. 시전 중 멈춤 |
| 별무리 | `star_swarm` | 20 | 16 | 0.4초 | 0.6 × 5 | 작은 별 5개가 주인공 주위를 1.5초 돌다가 가까운 적에게 하나씩 날아감(유도) |
| 달빛 칼날 | `moon_blade` | 14 | 10 | 0.15초 | 1.4 | 빛나는 칼을 만들어 앞을 반원으로 벰. 근접 마술, 지능으로 피해 계산 |
| 혜성 광선 | `comet_beam` | 36 | 초당 12 | 0.5초 후 유지 | 초당 3.0 | 누르고 있는 동안 굵은 광선. 이동 느려짐, 주변을 강하게 밝힘(조명). MP가 떨어지면 끊김 |

- 마술 데이터: `id`, `name`, `intelligence_required`, `mp_cost` 또는 `mp_per_second`, `cast_seconds`, `power`, 그리고 동작에 따라 `projectile`(9.2: `speed`, `range`, `size`, `count`, `homing`), `melee`(히트박스, 9.2와 같음), `beam`(`length`, `width`, `tick_seconds`), 선택 `fx`, `light`, `sfx`.
- 피해 = 마법 공격력(8.2) × 위력, 그다음은 9.3과 같다.
- 마술 빛 탄과 광선은 빛을 낸다(6.3 빛 데이터). 연출은 결과를 바꾸지 않는다.
- 마술은 상자·보스·상점(룬)으로 얻는다. 시작 이후 얻는 순서는 지역 설계(단계 18~19)에서 정한다.

## 8.7 세이브 포인트 (캣닢 쿠션)

세이브 포인트는 **캣닢 쿠션**이다. 고양이 귀 주인공이 폭신한 쿠션에 동그랗게 앉아 캣닢 향을 맡으며 쉬는 곳이다. 여기서 세 가지를 한다: **룬을 쓰고**(레벨업), **모든 상태를 회복하고**, **게임을 저장한다**.

### 놓기와 데이터

- 맵 엔티티로 놓는다(7.1 `entities`의 `"type": "save_point"`, `id`, `x`, `y`, 선택 `display_name`). 쿠션은 1칸 크기이고 지나갈 수 있다(주인공이 그 위에 앉는다).
- 쿠션 `id`는 게임 전체에서 겹치면 안 되고, 칸이 맵 안이면서 걸을 수 있는 칸이어야 한다(검증).
- 첫 지역(초원)에는 시작 위치 가까이에 하나를 둔다. 지역마다 1~2개, 보스 방 앞에는 하나를 둔다.

### 쉬기

- 쿠션에서 24픽셀 안에 서서 E를 누르면 "[E] 쉬기" 안내가 보이고 쉰다.
- **쉴 수 없을 때:** 주인공을 쫓고 있는 몬스터가 있거나(9.6 `chase` 이상), 맞은 지 3초가 안 지났으면 쉴 수 없다. "주변이 너무 소란스럽다" 알림을 보여 준다.
- 쉬면 이 순서로 처리한다(시뮬레이션, 한 박자 안에서):
  1. 주인공이 쿠션 가운데로 걸어가 앉는다(`resting` 상태, 게임 입력 차단).
  2. **모든 상태 회복:** HP·MP·스태미나를 최대로 채우고, 지침 상태와 (나중에 생길) 독 같은 상태 이상을 없앤다. 소비 아이템 중 "쉬면 다시 차는 것"(예: 회복 물약 충전, 확장)도 채운다.
  3. 부활 위치를 이 쿠션으로 정한다.
  4. 보스가 아닌 몬스터를 처음 자리에 다시 나타나게 한다(9.5).
  5. **자동 저장**한다(12.3). 저장이 실패하면 쉬기는 그대로 하고 "저장하지 못했다" 알림과 로그를 남긴다.
  6. 쿠션 메뉴를 연다.

### 쿠션 메뉴

| 항목 | 하는 일 |
|---|---|
| 레벨업 | 룬을 써서 능력치를 올린다(8.3). 룬이 모자란 항목은 흐리게 |
| 마술 칸 | 배운 마술을 마술 칸에 넣고 뺀다(8.6) |
| 저장 | 지금 슬롯에 한 번 더 저장한다(성공하면 화면 구석에 저장 아이콘) |
| 떠나기 | 메뉴를 닫고 일어난다 |

- 메뉴를 여는 동안 게임 시간은 흐르지 않는다(시뮬레이션 정지). 밖의 바람·파티클 연출은 계속된다.
- 확장 버전: 다른 쿠션으로 빠른 이동(23.2에서 결정).

### 처음 찾았을 때

- 처음에는 캣닢이 시든 쿠션이다(색이 바래고 빛이 없음). 처음 쉬면 캣닢이 톡 하고 피어나며 "캣닢 쿠션을 찾았다 — (쿠션 이름)" 배너가 뜬다.
- 찾은 쿠션 목록은 월드 깃발로 저장한다(한 번만 찾음, 테스트).

### 모습과 연출 (프레젠테이션 전용, 결과를 바꾸지 않음)

| 때 | 연출 |
|---|---|
| 평소 | 둥글고 통통한 자주색 쿠션, 네 귀퉁이에 금색 술. 위에 초록 캣닢 줄기 몇 개와 작은 연보라 꽃. 은은한 초록 빛(반지름 48, 0.3 Hz로 숨 쉬듯), 가끔 캣닢 조각이 위로 떠오름 |
| 다가가면 | 빛이 조금 밝아지고 "[E] 쉬기" 안내 |
| 쉬는 동안 | 주인공이 앉아 몸을 동그랗게 말고 꼬리를 감는다. 귀가 가끔 쫑긋. 작은 "z"와 하트 파티클, 그르릉 효과음, 빛이 따뜻한 색으로 바뀌고 화면 가장자리가 부드럽게 어두워짐 |
| 회복할 때 | HP·MP·스태미나 바가 트윈으로 차오르고, 주인공 주위에 초록 반짝임 |
| 떠날 때 | 주인공이 기지개를 켜고 일어난다(0.4초) |
| 쿠션에서 부활할 때 | 화면이 밝아지면 주인공이 쿠션 위에서 웅크린 채 눈을 뜨고 일어난다 |

- 그림: 쿠션 2장(시든·피어난), 캣닢 흔들림은 7단계의 흔들림 계산(`sway_offset`)을 그대로 쓴다. 주인공 그림에 "앉기", "웅크려 자기", "기지개" 동작을 추가한다.
- 효과 데이터: `fx/catnip_leaves.json`(떠오르는 잎), `fx/rest_hearts.json`(z·하트), `fx/rest_sparkle.json`(회복 반짝임). 소리: 그르릉, 쿠션에 앉는 폭신 소리, 잎 바스락.

### 테스트

- 쉬면 HP·MP·스태미나가 최대가 되고 부활 위치가 이 쿠션이 된다.
- 쫓는 몬스터가 있거나 맞은 직후에는 쉴 수 없다.
- 쉴 때 저장이 정확히 한 번 일어나고, 저장이 실패해도 회복은 된다.
- 처음 찾은 쿠션은 한 번만 기록된다.

# 9. 실시간 전투·몬스터 AI 명세

## 9.1 기본 원칙

- 모든 판정은 시뮬레이션(고정 박자)에서 한다. 그림 프레임은 판정에 맞춰 보여 줄 뿐이다.
- 전투 결과는 이벤트로 프레젠테이션에 알린다: `attack_started`, `hit`, `damage_applied`, `knockback`, `died`, `runes_gained`, `runes_lost`, `level_up`, `loot_spawned`.

## 9.2 공격 데이터

공격 하나는 데이터로 정의한다.

```json
{
  "schema_version": 1,
  "id": "sword_slash_1",
  "windup": 0.08,
  "active": 0.10,
  "recovery": 0.18,
  "cancel_window": [0.22, 0.36],
  "hitbox": {"offset": [18, -8], "size": [28, 24]},
  "power": 1.0,
  "knockback": 90,
  "hitstop": 0.06,
  "shake": 0.25,
  "fx": "fx/slash_spark.json",
  "sfx": "audio/sfx/sword_hit.wav",
  "next_combo": "sword_slash_2"
}
```

- 준비(windup) → 판정(active) → 후딜(recovery) 구간.
- 판정 구간 동안 히트박스와 겹친 대상은 **공격 한 번에 한 번만** 맞는다.
- 콤보: 취소 구간 안에 공격을 누르면 다음 공격으로 이어진다(입력 버퍼 사용).
- 공격 방향은 입력 방향 또는 바라보는 방향.
- 선택 필드 `mp_cost`(0 이상 정수, 기본 0): 공격을 시작할 때 MP를 그만큼 쓴다. MP가 모자라면 공격이 나가지 않고 MP 바가 깜빡인다.
- 선택 필드 `projectile`: 마법처럼 날아가는 공격. `speed`(px/s), `range`(px), `size`, 벽에 닿으면 사라짐, 대상 하나에 맞으면 사라짐. `count`(한 번에 몇 개, 기본 1)와 `homing`(유도 세기 0~1, 기본 0)을 둘 수 있다. 마술 목록과 데이터는 8.6에 있다.

## 9.3 피해 계산

```text
raw = attack_power * power
final = max(minimum_damage, raw - defense)  (치명타면 × crit_multiplier)
```

- 순수 함수로 분리하고 경계값 테스트를 한다.
- 최소 피해, 상한, 정수 범위, 무적 상태 순서를 명시한다.
- 난수는 시드가 있는 게임 전용 난수기로 만들어 테스트에서 재현할 수 있게 한다.

## 9.4 피격과 무적

- 맞으면 경직(`hit`) 시간 동안 행동 불가, 넉백 적용.
- 플레이어는 피격 후 짧은 무적 시간(기본 0.6초)과 깜빡임.
- 회피 중 무적 구간(기본 0.2초).

## 9.5 사망과 부활

- 몬스터: 사망 애니메이션 → 사라짐 연출(깜빡임·흩어지는 파티클) → 드롭·룬(쓰러뜨린 자리에서 주인공에게 빛 조각이 날아와 빨려 듦) → 플레이어가 세이브 포인트에서 쉬거나 쓰러졌다 부활하면 다시 나타남. 보스는 다시 나타나지 않는다.
- 플레이어: 슬로모션 + 화면 흑백 전환 → "쓰러졌다" 화면 → 마지막으로 쉰 세이브 포인트(8.7, 없으면 맵 시작 위치)에서 부활. 가진 룬의 절반을 잃고(8.3) 아이템·레벨·능력치는 잃지 않는다. HP·MP·스태미나는 가득 찬 상태로 부활한다.

## 9.6 몬스터 AI

상태: `idle`, `wander`, `notice`(느낌표 연출), `chase`, `windup`(공격 예고), `attack`, `recover`, `return`, `dead`.

- **공격 예고**는 반드시 화면에 보인다(번쩍임, 자세 변화, 바닥 경고 표시). 플레이어가 피할 수 있어야 한다.
- 데이터: 체력, 공격, 방어, 이동 속도, 감지 거리, 공격 거리, 추적 한계 거리, 공격 목록, 주는 룬, 드롭 표. 다시 나타나는 때는 9.5 규칙(캣닢 쿠션에서 쉬기·부활)을 따른다.
- 경로 찾기: 처음에는 직접 추적 + 벽 미끄러짐. 필요하면 타일 A*를 추가한다.
- AI는 시뮬레이션 박자 안에서 돌되, 화면 밖 멀리 있는 몬스터는 갱신 주기를 낮출 수 있다(측정 후).

## 9.7 드롭

- 드롭 표는 데이터로 정의하고, 게임 난수기로 결과를 정한다.
- 드롭된 아이템은 튀어 오르며 떨어지고(트윈), 반짝이며, 가까이 가면 자동으로 빨려 들어오듯 주워진다(설정으로 수동 줍기 가능).
- 같은 드롭은 한 번만 주워진다(테스트).

# 10. 아이템·인벤토리·장비 명세

## 10.1 아이템 정의와 인스턴스

- 정의(템플릿): id, 이름, 설명, 종류, 최대 중첩, 아이콘, 사용 효과, 장비 슬롯, 능력치, 희귀도(색 테두리).
- 인스턴스(실제 물건): 정의 id, 수량, 개별 속성(확장용).

## 10.2 인벤토리 규칙

- 슬롯 기반(기본 24칸), 중첩 규칙, 획득·사용·버리기·장착·해제·정렬.
- 가득 찼을 때 획득은 실패하고 아이템은 바닥에 남는다(알림 표시).
- 인벤토리 조작은 실패하면 아무것도 바뀌지 않아야 한다(전부 성공 또는 전부 실패). 테스트한다.

## 10.3 장비

- 슬롯: weapon, head, body, accessory.
- 무기는 무게(8.4)로 힘과 연결된다. 무기에는 레벨이나 능력치 요구 조건을 두지 않고, 들 수 있는 무게보다 무거우면 무거움 상태가 된다. 마술은 요구 지능(8.6)이 있다. 머리·몸·장신구의 무게와 조건은 확장 버전에서 정한다.
- 능력치 변화는 8.2의 한 계산 함수로만 적용한다.
- 무기는 캐릭터 그림 위에 겹쳐 그릴 수 있도록 그림 규칙을 정한다(확장 버전).

# 11. NPC·대화·퀘스트·상점

## 11.1 NPC와 대화

- NPC 데이터: id, 이름, 위치, 그림, 대화 id, 상호작용 종류(대화, 상점).
- 대화창: 글자가 하나씩 나타나는 타자기 효과, 말하는 사람 이름·초상화, 선택지, 건너뛰기.
- 대화 데이터는 노드 목록(대사, 선택지, 조건, 결과)으로 정의하고, 잘못된 연결을 검증한다.

## 11.2 퀘스트

- 유형: 몬스터 처치, 아이템 수집, NPC 대화, 지역 방문.
- 상태: `available` → `active` → `completed` → `reward_claimed`.
- 같은 보상은 한 번만 받는다(저장·불러오기를 거쳐도). 테스트한다.
- 화면: 퀘스트 목록, 진행 알림, 목표 방향 표시(선택).

## 11.3 상점

- 고정 상품 목록, 사고팔기.
- 가격(룬), 수량, 인벤토리 공간, 소지 룬을 확인하고, 거래는 전부 성공 또는 전부 실패한다.

# 12. 저장·불러오기

## 12.1 저장 위치와 형식

- 위치: `%APPDATA%\ProjectWIND\saves\slot_<n>.json` (슬롯 3개). 설정은 `%APPDATA%\ProjectWIND\settings.json`.
- 형식: JSON, 최상위에 `schema_version`, `game_version`, `saved_at`, `play_time_seconds`.
- 내용: 주인공 능력치(원본 다섯 개), 소지 룬, HP·MP 현재값, 마지막으로 쉰 세이브 포인트(쿠션 id), 찾은 쿠션 목록, 배운 마술과 마술 칸, 위치(맵·좌표), 인벤토리, 장비, 퀘스트 상태, 열린 상자·처치한 보스 등 월드 깃발, 게임 시간.
- 정확한 형식은 `docs/SAVE_FORMAT.md`에 확정한다.

## 12.2 안전한 저장

- **원자적 쓰기**: 임시 파일에 다 쓴 뒤 이름을 바꿔 덮어쓴다. 저장 중 꺼져도 이전 저장이 남는다.
- 바로 전 저장본을 `.bak`으로 하나 보관한다.
- 불러올 때 스키마 버전을 확인하고 검증한다. 이전 버전은 **변환 함수**로 올리고(버전마다 하나씩, 테스트), 모르는 미래 버전은 거부한다.
- 손상된 파일은 게임을 멈추지 않고 "불러올 수 없음"으로 표시하며 `.bak` 복구를 제안한다.
- 저장 파일 크기 상한(기본 4 MB)과 배열 길이 상한을 둔다.

## 12.3 저장 시점

- **기본 저장은 세이브 포인트(캣닢 쿠션, 8.7)에서 한다.** 쉬면 지금 슬롯에 자동 저장하고, 쿠션 메뉴의 "저장"으로 한 번 더 저장할 수 있다. 쿠션이 아닌 곳에서는 직접 저장할 수 없다.
- 쓰러졌을 때는 룬을 잃은 직후 지금 슬롯과 자동 저장 슬롯을 모두 저장한다(저장 파일을 바꿔 치기하거나 자동 저장을 불러와서 룬을 되살리지 못하게).
- 지역 전환 시 자동 저장 슬롯에만 저장한다(게임이 갑자기 꺼졌을 때 대비). 불러오면 그 지역 입구에서 시작하고, 부활 위치는 마지막 쿠션 그대로다.
- 저장 중임을 화면 구석 아이콘으로 표시한다.

# 13. UI·입력·오디오

## 13.1 화면 흐름

```text
타이틀 → (새 게임 → 이름 입력) / (이어하기 → 슬롯 선택) / 설정 / 종료
        ↓
       필드 ⇄ 일시정지 메뉴(인벤토리, 장비, 마술, 능력치, 퀘스트, 설정, 저장 안내, 타이틀로)
       필드 ⇄ 쿠션 메뉴(레벨업, 마술 칸 바꾸기, 저장, 떠나기)  ← 캣닢 쿠션에서
        ↓
       쓰러짐 화면(잃은 룬 표시) → 마지막 쿠션에서 부활
```

타이틀 화면도 살아 있게 만든다: 배경 장면(바람에 흔들리는 풀, 파티클, 시간대 순환), 로고 등장 트윈.

## 13.2 필드 HUD

- 왼쪽 위: HP·MP·스태미나 바(지연 바). 바 길이는 최대값에 비례해 늘어난다(능력치를 올리면 바가 길어짐). 스태미나 바는 다 차 있으면 잠시 뒤 흐려지고, 쓰기 시작하면 다시 진해진다
- 오른쪽 아래: 소지 룬 숫자. 룬을 얻으면 "+12"가 잠깐 뜨고 숫자가 굴러가듯 올라간다(트윈). 쓰러져서 잃으면 빨갛게 줄어든다
- 왼쪽 아래: 지금 무기와 고른 마술 아이콘(마술 이름, MP가 모자라면 흐리게)
- 레벨과 능력치는 HUD에 두지 않고 메뉴·레벨업 화면에서 보여 준다
- 단축 아이템 칸
- 지역 이름 배너, 획득 알림
- 상호작용 안내(“[E] 말하기”, 캣닢 쿠션 앞에서는 “[E] 쉬기”)
- HUD는 화면 가장자리에 최소한으로. 전투를 가리지 않는다.

## 13.3 UI 요구사항

- 입력 포커스 관리(메뉴가 열리면 게임 입력 차단)
- 키보드 우선, 마우스 지원
- 창 크기 변경 대응(논리 해상도 유지)
- 글자 잘림 검사
- 설정 저장: 볼륨, 창/전체 화면, 화면 배율, 키 설정, 화면 흔들림·번쩍임 세기

## 13.4 기본 키

| 동작 | 키 |
|---|---|
| 이동 | 방향키 / WASD |
| 공격 | J 또는 Z |
| 마술 쓰기 | L 또는 C (혜성 광선은 누르고 있는 동안) |
| 마술 고르기 | Q (마술 칸을 차례로) |
| 회피 | K 또는 X / Space |

| 상호작용 | E 또는 Enter |

키 설정은 바꿀 수 있다. 단계 1의 "Esc = 종료"는 일시정지 메뉴가 생기는 단계에서 "Esc = 메뉴"로 바뀐다.

# 14. 콘텐츠 데이터 형식 및 검증

## 14.1 원칙

맵, 타일셋, 스프라이트, 파티클, 빛, 몬스터, 공격, 무기, 마술, 능력치 곡선, 레벨 비용, 아이템, 드롭 표, NPC, 대화, 퀘스트, 날씨 표는 모두 데이터 파일이다. 모든 파일에 `schema_version`을 넣고, 불러오기 전에 검증한다. 파일 위치는 콘텐츠 루트 안으로 제한한다.

## 14.2 몬스터·무기·마술 예시

```json
{
  "schema_version": 1,
  "id": "slime_green",
  "name": "초록 슬라임",
  "sprite": "sprites/slime_green.json",
  "max_hp": 30,
  "attack_power": 4,
  "defense": 0,
  "move_speed": 40,
  "rune_reward": 12,
  "detect_range": 120,
  "leash_range": 260,
  "attacks": ["attacks/slime_hop.json"],
  "drop_table": "drops/slime.json",
  "death_fx": "fx/slime_burst.json"
}
```

무기 (`content/weapons/greatsword.json`):

```json
{
  "schema_version": 1,
  "id": "greatsword",
  "name": "대검",
  "weight": 14,
  "base_power": 26,
  "strength_scaling": 1.2,
  "stamina_per_attack": 26,
  "attacks": ["attacks/greatsword_1.json", "attacks/greatsword_2.json"]
}
```

마술 (`content/spells/star_swarm.json`):

```json
{
  "schema_version": 1,
  "id": "star_swarm",
  "name": "별무리",
  "intelligence_required": 20,
  "mp_cost": 16,
  "cast_seconds": 0.4,
  "power": 0.6,
  "projectile": { "speed": 220, "range": 260, "size": [6, 6], "count": 5,
                  "homing": 0.8, "orbit_seconds": 1.5 },
  "fx": "fx/star_trail.json",
  "light": { "radius": 40, "color": "#9cc8ff", "intensity": 0.7 }
}
```

- 검증: 무게·공격력·보정은 0 이상, 공격 목록 1~6개(파일 존재), 요구 지능 1~60, `mp_cost`와 `mp_per_second` 중 하나만, 동작(`projectile`/`melee`/`beam`) 중 하나만.

## 14.3 파티클 효과 예시

단계 4에서 확정한 형식이다. 모든 필드와 범위는 `docs/ENGINE.md` "Particle effect" 절에 있다.

```json
{
  "schema_version": 1,
  "id": "slash_spark",
  "shape": "soft",
  "blend": "add",
  "burst": 12,
  "lifetime": [0.15, 0.35],
  "speed": [60, 160],
  "spread": 70,
  "gravity": 200,
  "drag": 3.0,
  "start_size": 3,
  "end_size": 0,
  "start_color": "#fff6c8",
  "end_color": "#ff8a2a00"
}
```

점 그림은 파일이 아니라 코드로 만든 흰색 모양(`soft` 동그라미, `pixel` 네모)에 색을 곱해 쓴다.

## 14.4 검증

다음을 검출한다: 중복 ID, 필수 필드 누락, 잘못된 참조(없는 그림·소리·맵·아이템·스폰), 숫자 범위 위반, 비정상적으로 큰 파일·배열, 모르는 스키마 버전, 대화·퀘스트의 끊긴 연결.

실패하면 그 콘텐츠를 불러오지 않고 파일명과 필드 경로(예: `layers[0].tiles[1]`)가 담긴 오류를 출력한다. 오류는 최대 20개까지 보여 준다. `tools/content_validator`로 전체 콘텐츠를 한 번에 검사할 수 있게 한다.

# 15. 안정성·데이터 무결성

싱글 플레이이므로 치트 방지는 하지 않는다. 대신 다음을 지킨다.

- 콘텐츠·저장 파일은 손상되거나 잘못 편집될 수 있는 외부 입력이다. 크기·길이·범위를 검사하고, 실패해도 크래시하지 않는다.
- 파일 경로는 콘텐츠 루트(또는 저장 폴더) 밖으로 나갈 수 없다(`..`, 절대 경로, 드라이브 문자, 제어 문자 거부).
- 저장은 원자적으로 하고 백업을 남긴다(12.2).
- 리소스 누락은 자리 표시 그림·무음으로 대체하고 로그를 남긴다.
- 예외적인 오류는 로그 파일(`%APPDATA%\ProjectWIND\logs`)에 남겨 문제를 재현할 수 있게 한다.
- 비밀 정보는 없지만, 사용자 경로 등 개인 정보를 불필요하게 로그에 남기지 않는다.

# 16. 성능·관측 가능성

## 16.1 초기 목표(측정할 가설)

- 일반 테스트 맵, 화면 안 엔티티 50개, 파티클 2,000개, 빛 32개에서 60 FPS.

- 맵 전환(불러오기 포함) 0.5초 이하.
- 저장 0.1초 이하.

이 수치는 실제 하드웨어에서 측정한 뒤 확정하거나 고친다.

## 16.2 지표

FPS, 프레임 시간, 시뮬레이션 시간, 놓친 박자, 그리기 호출 수, 파티클 수·버린 수, 빛 수, 엔티티 수, 텍스처 수·캐시 적중, 메모리.

## 16.3 로그

수준: trace/debug(개발), info(주요 상태 변화), warn(복구 가능), error(작업 실패), critical(계속 불가). 로그 파일은 크기 제한과 개수 제한으로 회전한다.

# 17. 테스트·품질 기준

## 17.1 단위 테스트(SDL 없이)

- 좌표 변환, 카메라
- 자유 이동 충돌(벽 미끄러짐, 모서리 보정, 대각선 속도)
- 공격 구간·히트박스·한 번만 맞기
- 피해 계산 경계값
- 상태 머신 전이
- 룬 비용·능력치 곡선·레벨업 전부 성공 또는 전부 실패·쓰러질 때 룬 절반 손실
- 인벤토리 중첩·가득 참·전부 성공 또는 전부 실패
- 장비 능력치 계산
- 퀘스트 상태 전이와 보상 한 번
- 파티클 시뮬레이션(수명, 상한), 트윈 이징, 시간대 색 보간
- 저장 직렬화 왕복, 버전 변환, 손상 파일 거부
- 콘텐츠 검증

## 17.2 시뮬레이션 재현 테스트

입력 기록(박자별 입력)과 난수 시드로 시뮬레이션을 돌려 같은 결과(위치, HP, 드롭)가 나오는지 확인한다. 버그 재현에도 쓴다.

## 17.3 화면 확인

- 단계 완료 때 실제 클라이언트를 실행해 장면을 보고, F12 스크린샷을 남긴다.
- 렌더 큐 수준(무엇을 어떤 순서로 그리는지)은 단위 테스트로 검사한다.
- 픽셀 단위 이미지 비교 테스트는 하드웨어 차이 때문에 필수로 하지 않는다. 필요하면 소프트웨어 렌더러로 별도 검토한다.

## 17.4 회귀 테스트

버그를 고치면 재현 테스트를 추가한다.

## 17.5 완료 선언 기준

코드 구현, 빌드 성공, 관련 테스트 실행, 실제 실행 확인(눈에 보이는 기능은 화면 확인), 문서 업데이트, 알려진 제한 사항 기록이 모두 되어야 완료다. 실행하지 않은 테스트를 통과했다고 보고하지 않는다.

# 19. 단계별 개발 계획 및 완료 기준

전체를 **21개 단계(0~20)**로 나눈다. 단계 하나는 보통 며칠 안에 끝낼 수 있는 크기이고, 각 단계는 **직접 보고 확인할 수 있는 장면**으로 끝난다. 단계 안에서도 작업을 더 작게 나눠 하나씩 빌드·테스트한다.

| 묶음 | 단계 | 이름 | 끝나면 보이는 장면 |
|---|---|---|---|
| 기반 | 0 ✅ | 환경·저장소 | 빈 창이 뜨고 테스트가 돈다 |
| | 1 ✅ | 최소 엔진 | 맵 위를 캐릭터가 걷는다 |
| | 2 ✅ | 정리와 자유 이동 | 8방향 이동, 벽 미끄러짐, 구르기 |
| 비주얼 | 3 ✅ | 렌더링 기반 | 같은 화면이 렌더 타깃을 거쳐 그려지고, 트윈·스크린샷이 동작 |
| | 4 ✅ | 파티클 시스템 | 데이터로 정의한 꽃잎·반딧불이 맵에 떠다닌다 |
| | 5 ✅ | 조명 | 어두운 동굴에서 횃불이 깜빡이며 주변을 밝힌다 |
| | 6 ✅ | 시간과 날씨 | 초원이 낮→노을→밤으로 바뀌고 비가 내렸다 그친다 |
| | 7 ✅ | 살아 있는 월드와 지역 전환 | 물이 반짝이고 풀이 흔들리며, 출구로 가면 페이드 후 다음 맵 |
| UI 기초 | 8 ✅ | 텍스트와 UI 기초 | 한글 지역 이름 배너가 트윈으로 나타나고, Shift로 달리면 스태미나 바가 준다 |
| 전투 | 9 | 공격 기초 | 허수아비를 칼로 때리면 HP가 줄고, 별빛 조각을 쏘면 MP가 준다 |
| | 10 | 타격감 | 때릴 때 멈칫·번쩍·밀려남·흔들림·피해 숫자 |
| | 11 | 몬스터 AI | 슬라임이 쫓아오고 공격 예고 후 덤빈다 |

| 성장 | 13 | 룬과 레벨업 | 슬라임을 잡아 모은 룬으로 쿠션에서 원하는 능력치를 올린다 |
| | 14 | 드롭과 인벤토리 | 아이템이 튀어나오고 빨려 들어와 인벤토리에 쌓인다 |
| | 15 | 장비와 메뉴 | 검을 바꾸면 능력치가 바뀌고, 일시정지 메뉴가 열린다 |

# 20. Claude 개발 운영 규칙

## 20.1 작업 시작 전

1. 현재 저장소 구조를 조사한다.
2. README와 관련 설계 문서를 읽는다.
3. 현재 빌드와 테스트 상태를 확인한다.
4. 관련 코드와 인터페이스를 살핀다.
5. 변경 파일과 완료 기준을 제시한다.

기존 코드를 무조건 새로 만들거나 덮어쓰지 않는다. 방향 전환으로 필요 없어진 코드는 해당 단계 작업으로 명시하고 제거한다.

## 20.2 작은 작업 단위

한 작업에서 하나의 기능 경계만 구현한다. 예: 파티클 데이터 형식 → 파티클 시뮬레이션과 테스트 → 그리기 연결 → 실제 효과 데이터.

## 20.3 모호한 요구

- 기존 명세와 충돌하는지 먼저 확인한다.
- 위험이 낮으면 가장 단순하고 확장 가능한 기본안을 고른다.
- 저장 형식, 데이터 삭제처럼 되돌리기 어려운 결정은 변경 전 계획과 영향을 밝힌다.
- 중요한 결정은 `docs/DECISIONS/`에 기록한다.

## 20.4 테스트와 보고

작업 완료 보고 형식은 저장소 루트 `CLAUDE.md`의 "개발 작업 완료 보고 규칙"(8개 항목)을 따른다. 이 문서에 따로 적지 않는다.

실제로 실행하지 않은 명령이나 테스트를 실행했다고 말하지 않는다.

## 20.5 금지 사항

- 전체 게임을 한 번에 만들려고 하지 않는다.
- 빌드 오류를 숨기거나 테스트를 지워 통과시키지 않는다.
- 무관한 코드를 대량으로 포맷하거나 재작성하지 않는다.
- 명세에 없는 큰 기능을 임의로 추가하지 않는다.
- 기존 인터페이스를 조용히 바꾸지 않는다.
- TODO만 작성하고 구현했다고 보고하지 않는다.
- 저작권이 있는 그림·음악·폰트를 가져오지 않는다.
